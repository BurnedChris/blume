title: Cookie consent
description: Use c15t for script loading and consent, with an offline banner, a c15t backend, or an existing Osano or Fides installation.
---

Blume uses c15t to manage scripts, consent changes, and analytics event delivery. Adding an [analytics adapter](/docs/configuration/analytics) automatically enables a c15t banner in offline mode. No account or backend is required for local testing. Sites with no analytics and no consent configuration load no c15t runtime or UI.

```ts blume.config.ts
import { defineConfig } from "blume";
import { googleTagManager } from "blume/analytics";

export default defineConfig({
  analytics: [googleTagManager({ id: "GTM-EXAMPLE" })],
});
```

GTM starts with c15t's Google Consent Mode defaults before its container loads. The banner asks for a choice and c15t sends updates afterward. Tags inside the container must honor those signals; Blume cannot inspect or correct your GTM configuration.

## Connect a backend

Use `c15t()` from `blume/consent` to configure the Astro integration. Hosted mode works with an Inth endpoint or a self-hosted c15t backend. Configure the backend's policy rules and allowed origins for your site.

```ts blume.config.ts
import { defineConfig } from "blume";
import { c15t } from "blume/consent";

export default defineConfig({
  consent: c15t({
    mode: { type: "hosted", url: "https://consent.example.com" },
    legalLinks: { privacyPolicy: { href: "/privacy" } },
    clientEntrypoint: "./consent.client.ts",
  }),
});
```

`c15t()` without a mode uses a global opt-in policy. Offline mode stores choices in the browser and does not provide a server-side consent record or centrally managed policy. It is intended here for local testing; review backend and policy requirements before production use.

The c15t banner and preferences use c15t's copy and translations. Configure `i18n`, `theme`, `legalLinks`, and `consentCategories` through `c15t()`. The runtime follows Blume's light/dark setting and document language. When supplying multiple languages, include their c15t message bundles in `i18n.messages`.

## Use the full script SDK

Every named public `@c15t/scripts` subpath is available under `blume/scripts` with the same exports and types. Scripts contain lifecycle callbacks, so put them in a browser module instead of the JSON configuration snapshot.

```ts consent.client.ts
import { googleTagManager } from "blume/scripts/google-tag-manager";
import { metaPixel } from "blume/scripts/meta-pixel";
import type { ConsentClientOptions } from "blume/consent";

export default {
  scripts: [
    googleTagManager({ id: "GTM-EXAMPLE" }),
    metaPixel({ pixelId: "123456789" }),
  ],
} satisfies ConsentClientOptions;
```

Point `consent.clientEntrypoint` at this module. Use the SDK's `registry` export to discover integrations. Existing `blume/analytics` factories remain supported and are translated into c15t SDK calls. The [analytics migration guide](/docs/configuration/analytics-migration) covers every adapter, option mapping, mixed configurations, and `pageviews` for SDKs that need explicit router events.

Legacy `analytics` adapters are disabled in `blume dev`. Scripts explicitly supplied in a client entrypoint are under your control and run in development too; use `import.meta.env.PROD` if you want to disable them locally.

## Keep Osano or Fides

An external CMP owns the banner, preferences, persistence, and consent records. c15t reads its decisions and manages scripts. Blume does not display a second banner or save an imported provider decision as a c15t receipt.

```ts blume.config.ts
import { defineConfig } from "blume";
import { ethyca } from "blume/consent";

export default defineConfig({
  consent: ethyca({
    privacyCenter: "https://privacy.example.com",
    notice: "analytics",
    categories: { marketing: "advertising" },
    clientEntrypoint: "./consent.client.ts",
  }),
});
```

For Fides, `notice` defaults to `analytics`. `categories` maps additional c15t categories to your Fides notice keys. Values `true`, `opt_in`, and `acknowledge` grant the mapped category; other or missing values deny it. Configure those notices correctly for your processing.

```ts
import { osano } from "blume/consent";

const consent = osano({
  customerId: "your-customer-id",
  configId: "your-config-id",
  clientEntrypoint: "./consent.client.ts",
});
```

Osano maps `analytics === true` to c15t measurement consent. Its optional `categories` map names the additional boolean consent properties your Osano setup exposes. Unmapped categories stay denied. Failed or unavailable providers do not grant optional consent. Do not configure the external CMP to independently load the same vendor scripts.

## Loading and withdrawal

c15t owns one script runtime across Astro navigation. Each SDK helper defines whether its script waits for consent or loads earlier with denied-state behavior. `alwaysLoad`, Consent Mode, or cookieless operation is not permission to send arbitrary analytics events. Blume's custom events are dispatched only when measurement and the integration's own consent gates allow them. Denied events are discarded.

Blume enables c15t's `reloadOnRevocation` option by default to stop SDKs that cannot unload after executing. Set it to `false` only after verifying every configured vendor's withdrawal behavior. Removing a script element alone cannot undo JavaScript that already ran.

The footer's **Cookie settings** control opens the active provider's preferences. `native({ policy: "/privacy" })` remains a compatibility option for the offline c15t banner; old `blume-consent` storage is not promoted into a c15t record, so existing visitors will be asked again. Old `i18n.ui.consent` banner-copy overrides should move to c15t's `i18n` options.

Centralizing this behavior reduces the consent-sensitive code Blume maintains. It does not make a site automatically compliant: policy, notices, provider configuration, processing purposes, and actual network/storage behavior still need review.
