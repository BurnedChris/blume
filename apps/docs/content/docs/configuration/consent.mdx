Blume uses [c15t](https://c15t.com) to ask readers for consent and to load your scripts only as their answer allows. Add a `consent.ts` to your project root, next to `blume.config.ts`, and list your scripts in it. Blume finds the file by name and shows a consent banner; nothing in `blume.config.ts` is required.

```ts consent.ts
import { defineConsent } from "blume/consent/client";
import { plausibleAnalytics } from "blume/integrations/plausible-analytics";

export default defineConsent({
  scripts: [plausibleAnalytics({ domain: "docs.example.com" })],
});
```

[Integrations](/docs/configuration/integrations) lists every vendor helper and covers pageviews, custom scripts, and testing. A site with no `consent.ts`, no `consent` config, and no deprecated `analytics` list loads no c15t code at all.

## Connect a backend

On its own, `consent.ts` runs c15t in offline mode with an opt-in policy everywhere. Choices are stored in the reader's browser, with no server-side record and no central policy. That suits trying things out; before production, decide whether you need a backend.

To use one, set `consent` with c15t's `hosted()` mode, pointing at an [Inth](https://inth.com) project or a self-hosted c15t backend. Configure its policy rules and allowed origins for your site. `consent.ts` stays as it is.

```ts blume.config.ts
import { defineConfig } from "blume";
import { c15t, hosted } from "blume/consent";

export default defineConfig({
  consent: c15t({
    mode: hosted({ url: "https://consent.example.com" }),
  }),
});
```

`blume/consent` also exports `offline()`, and `offline({ policyRules })` keeps the offline mode with your own rules.

### Serve the banner from your own site

With a server [deployment](/docs/deployment) such as `vercel()` or `node()`, use `manifest()` instead of `hosted()`. The reader's browser then asks your site, not the backend, which banner to show:

```ts blume.config.ts
import { defineConfig } from "blume";
import { c15t, manifest } from "blume/consent";
import { vercel } from "blume/deploy";

export default defineConfig({
  consent: c15t({
    mode: manifest({ backendURL: "https://consent.example.com" }),
  }),
  deployment: vercel(),
});
```

Blume downloads the backend's policy when it builds and bundles it into the server, so the banner doesn't wait on a request to the backend. Readers' choices still go to the backend. Because the policy is fixed at build time:

- Rebuild after changing policies, translations, or vendors in the backend.
- The build fails if it can't reach the backend, and `blume dev` downloads the policy when it starts.

To pick up policy changes without a rebuild, set `buildManifest: false` on `c15t()`. The server then downloads the policy when it first needs it and caches it. A static site can't use `manifest()`; use `hosted()` there.

## Customize the banner

The banner and the preferences dialog take the site's theme: its colors, corners, shadows, and body font, plus its light/dark toggle. On wide screens the banner fits the space beside the article instead of covering it. Reject, Accept, and Customize share one button style, so no answer looks preferred.

Change the wording, links, categories, or look with c15t's options on `c15t()`:

```ts blume.config.ts
import { defineConfig } from "blume";
import { c15t } from "blume/consent";

export default defineConfig({
  consent: c15t({
    legalLinks: { privacyPolicy: { href: "/privacy" } },
    theme: { colors: { primary: "oklch(0.55 0.2 260)" } },
  }),
});
```

- `legalLinks` puts your privacy policy and other legal pages in the banner and dialog.
- `theme` overrides Blume's defaults one token at a time; tokens you leave out keep the site's values.
- `i18n` sets the copy. The banner follows the page's language; for a multilingual site, include c15t's message bundle for each language in `i18n.messages`.
- `consentCategories` lists the categories the dialog offers.
- `presentation.prompt.primaryActions`, for example `["accept"]`, highlights an action if your policy allows it.

## Keep Osano or Fides

An existing consent manager can stay in charge of the banner, preferences, and consent records while c15t loads your scripts. Blume shows no second banner and doesn't copy the provider's decisions into c15t. Keep your scripts in `consent.ts`; the provider only decides what they may do, so don't let it load the same vendors separately.

For Fides, `notice` names the privacy notice that covers analytics (default `analytics`), and `categories` maps further c15t categories to your notice keys. `true`, `opt_in`, and `acknowledge` grant a category; anything else denies it.

```ts blume.config.ts
import { defineConfig } from "blume";
import { ethyca } from "blume/consent";

export default defineConfig({
  consent: ethyca({
    privacyCenter: "https://privacy.example.com",
    notice: "analytics",
    categories: { marketing: "advertising" },
  }),
});
```

For Osano, `analytics === true` grants measurement, and `categories` maps further c15t categories to the boolean consent properties your Osano setup exposes.

```ts
import { osano } from "blume/consent";

const consent = osano({
  customerId: "your-customer-id",
  configId: "your-config-id",
});
```

Categories you don't map stay denied, and so does everything while the provider is missing or fails to load.

## Cookie settings link

The site footer has a **Cookie settings** link that reopens the preferences dialog, or the provider's preferences with Osano and Fides. It shows while the reader's policy asks for consent (opt-in, opt-out, or IAB) or grants privacy rights, and always with Osano or Fides. A policy that needs no consent and grants no rights hides it.

If you replace the footer with a [`Footer` override](/docs/configuration/customization), give any element a `data-blume-consent-open` attribute to open preferences from it.

## Withdrawal and reload

When a reader withdraws consent they had given, Blume reloads the page. Removing a script tag can't stop JavaScript that already ran, so the reload starts a page with only the scripts still allowed. Turn it off with `c15t({ reloadOnConsentRevoked: false })` only after checking that every vendor you load stops on its own.

## Upgrading from native()

`native({ policy: "/privacy" })` still works and runs the same c15t banner, with `policy` as its privacy link. Answers stored by Blume's old banner aren't carried over, so returning readers are asked again. Banner copy set through `i18n.ui.consent` no longer applies; move it to `c15t({ i18n })`.

Blume handles consent mechanics for you, but not compliance: your policy, notices, category choices, and vendors' actual behavior still need review.
