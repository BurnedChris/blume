title: Cookie consent
description: Use c15t for script loading and consent, with an offline banner, a c15t backend, or an existing Osano or Fides installation.
---

Blume uses c15t to manage scripts, consent changes, and analytics event delivery. Add a `consent.ts` to your project root, next to `blume.config.ts`, and list your scripts in it. Blume finds the file on its own and turns on an offline consent banner; no config is needed. Sites with no `consent.ts`, no analytics, and no consent configuration load no c15t runtime or UI.

```ts consent.ts
import { defineConsent } from "blume/consent/client";
import { googleTagManager } from "blume/integrations/google-tag-manager";

export default defineConsent({
  scripts: import.meta.env.PROD
    ? [googleTagManager({ id: "GTM-EXAMPLE" })]
    : [],
});
```

Scripts carry lifecycle callbacks, so they live in this browser module rather than in `blume.config.ts`, which Blume serializes. Existing `analytics` lists also enable offline consent automatically, but that API is deprecated and will be removed in the next major release. Follow the [migration guide](/docs/configuration/analytics-migration).

GTM starts with c15t's Google Consent Mode defaults before its container loads. The banner asks for a choice and c15t sends updates afterward. Tags inside the container must honor those signals; Blume cannot inspect or correct your GTM configuration.

## Connect a backend

Use `c15t()` from `blume/consent` to configure the Astro integration, with c15t's `hosted()`, `manifest()`, or `offline()` mode. Hosted mode works with an Inth endpoint or a self-hosted c15t backend. Configure the backend's policy rules and allowed origins for your site. Your `consent.ts` stays as it is.

```ts blume.config.ts
import { defineConfig } from "blume";
import { c15t, hosted } from "blume/consent";

export default defineConfig({
  consent: c15t({
    mode: hosted({ url: "https://consent.example.com" }),
    legalLinks: { privacyPolicy: { href: "/privacy" } },
  }),
});
```

`c15t()` without a mode, and a `consent.ts` on its own, use `offline()` with a global opt-in policy. Offline mode stores choices in the browser and does not provide a server-side consent record or centrally managed policy. It is intended here for local testing; review backend and policy requirements before production use.

The c15t banner and preferences use c15t's copy and translations. Configure `i18n`, `theme`, `legalLinks`, and `consentCategories` through `c15t()`. The banner and dialog follow Blume's light/dark setting and document language, and use the site's body font unless `theme.typography.fontFamily` sets another. When supplying multiple languages, include their c15t message bundles in `i18n.messages`.

## Use the full script SDK

The [integrations guide](/docs/configuration/integrations) lists the available vendors and covers setup, navigation pageviews, custom scripts, and verification.

Every named public `@c15t/scripts` subpath is available under `blume/integrations` with the same exports and types. Import `defineConsent` from `blume/consent/client`, not `blume/consent`: `consent.ts` runs in the browser, and that entry keeps the config-side code out of your pages.

```ts consent.ts
import { googleTagManager } from "blume/integrations/google-tag-manager";
import { metaPixel } from "blume/integrations/meta-pixel";
import { defineConsent } from "blume/consent/client";

export default defineConsent({
  scripts: [
    googleTagManager({ id: "GTM-EXAMPLE" }),
    metaPixel({ pixelId: "123456789" }),
  ],
});
```

Use the SDK's `registry` export to discover integrations. Deprecated `blume/analytics` factories are translated into c15t SDK calls for this release and will be removed in the next major release. The [analytics migration guide](/docs/configuration/analytics-migration) covers every adapter, option mapping, mixed configurations, and `pageviews` for SDKs that need explicit router events.

Legacy `analytics` adapters are disabled in `blume dev`. Scripts in `consent.ts` are under your control and run in development too; use `import.meta.env.PROD` if you want to disable them locally.

## Keep Osano or Fides

An external CMP owns the banner, preferences, persistence, and consent records. c15t reads its decisions and manages scripts. Blume does not display a second banner or save an imported provider decision as a c15t receipt.

```ts blume.config.ts
import { defineConfig } from "blume";
import { ethyca } from "blume/consent";

export default defineConfig({
  consent: ethyca({
    privacyCenter: "https://privacy.example.com",
    notice: "analytics",
    categories: { marketing: "advertising" },
  }),
});
```

For Fides, `notice` defaults to `analytics`. `categories` maps additional c15t categories to your Fides notice keys. Values `true`, `opt_in`, and `acknowledge` grant the mapped category; other or missing values deny it. Configure those notices correctly for your processing.

```ts
import { osano } from "blume/consent";

const consent = osano({
  customerId: "your-customer-id",
  configId: "your-config-id",
});
```

Blume still reads your scripts from `consent.ts`; the provider only decides what they may do. Osano maps `analytics === true` to c15t measurement consent. Its optional `categories` map names the additional boolean consent properties your Osano setup exposes. Unmapped categories stay denied. Failed or unavailable providers do not grant optional consent. Do not configure the external CMP to independently load the same vendor scripts.

## Loading and withdrawal

c15t owns one script runtime across Astro navigation. Each SDK helper defines whether its script waits for consent or loads earlier with denied-state behavior. `alwaysLoad`, Consent Mode, or cookieless operation is not permission to send arbitrary analytics events. Blume's custom events are dispatched only when measurement and the integration's own consent gates allow them. Denied events are discarded.

Blume enables c15t's `reloadOnConsentRevoked` option by default to stop SDKs that cannot unload after executing. Set it to `false` only after verifying every configured vendor's withdrawal behavior. Removing a script element alone cannot undo JavaScript that already ran.

The footer's **Cookie settings** control opens the active provider's preferences. It appears only while the visitor's policy asks for consent (opt-in, opt-out, or IAB) or grants privacy rights, and whenever Osano or Fides is the provider. A `none` policy with no rights hides it. `native({ policy: "/privacy" })` remains a compatibility option for the offline c15t banner; old `blume-consent` storage is not promoted into a c15t record, so existing visitors will be asked again. Old `i18n.ui.consent` banner-copy overrides should move to c15t's `i18n` options.

Centralizing this behavior reduces the consent-sensitive code Blume maintains. It does not make a site automatically compliant: policy, notices, provider configuration, processing purposes, and actual network/storage behavior still need review.
